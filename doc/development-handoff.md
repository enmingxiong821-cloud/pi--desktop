# 实施交接资料包

> 本文件是设计交接材料。资料整理与代码实现分阶段进行。

## 一句话目标

Windows 优先的 Electron Pi 工作台。启动后运行真实 Pi TUI，侧边图形辅助管理项目、模型与能力；按当前项目和任务，在用户已信任、已配置且策略允许的范围内，自主选择/调用 Pi Skills 和 MCP，不要求每次人工点选，但不得越过安全授权边界。

## 已确认、不能重新脑补的选择

- 主入口是真实 Pi 终端，不是 RPC 聊天替代终端。
- 桌面宿主已选 Electron；PTY、xterm.js 是验证候选，不代表已批准并安装了具体版本。
- Pi 是实际会话/Agent/工具/模型状态的事实源。桌面辅助面板不能显示“已成功”除非运行时确认。
- 项目/任务驱动 Skills/MCP 自主选用是已确认产品目标：授权 allow 范围内可直接自主调用；deny 永不调用；confirmFirst 必须人工确认。
- 支持模型切换与自定义中转站；真实凭据不能写到 UI renderer、源码、日志、截图或导出配置。
- 用户新增已确认目标：按项目任务点自动选择模型，并联合选择 Skills/MCP。目标是质量达标后优化总耗时与费用，不是无条件保证最高质量/最低费用/最快速度。必读 [任务路由模块](task-routing-design.md)。
- 建议首版不引入数据库，优先 Electron 主进程 IPC 管理 PTY，不必先加 HTTP 后端；这些是蓝图建议，候选端口 1420/2420 不是已分配端口。
- 原型布局不是正式视觉验收。桌面服务和性能尚未验证。

## 产品行为契约

### 项目绑定

- 用户主动选择目录；规范化并显示实际工作目录。
- 每个项目分别解析 Pi 当前版本实际可发现的 Skills、MCP servers/tools、配置来源、项目 trust 和已启用状态。
- 切换项目时清理上一项目的能力候选/运行缓存，不读取其他未打开项目，不私自扫描磁盘。
- Pi 未信任项目时不可读取/加载项目 `.pi/mcp.json` 作为可执行配置。信任交由 Pi 原生流程确认。

### Skills 自动选择和调用

- 通过 Pi 原生发现清单的 Skill 名称、描述路由；全量 `SKILL.md` 仍由 Pi 在匹配任务后读取。
- 只考虑当前项目 Pi 已发现且项目策略允许的 Skills。授权范围内，Pi 可自行选择；不可要求每个 Skill 都再弹窗。
- 用户可固定、禁用或明确指定 `/skill:name`。
- 界面必须分别显示“发现、项目允许、任务候选、Pi 已选/载入、调用后结果”。不能仅凭任务文本匹配就声称实际执行。
- 不在 Electron 中运行 Skill 的脚本，也不 fork 出另一套 skill 解释/Agent 引擎。

### MCP 自主路由

- 先按 Pi 项目 trust 和实际 runtime 可用性，再按项目 `allow/deny/confirmFirst` 及工具任务描述筛选。
- 只有当前项目可访问、服务器已启用、已认证/已连接、项目策略允许的 tools 能进入候选；`deny` 优先于 `allow`。
- allow 范围内已获准的普通调用由 Pi 模型自主发起，不按次弹窗；confirmFirst 项目规则和 Pi 的权限扩展/确认逻辑生效。
- 新服务器启用、未授权项目配置、新凭据、敏感文件外发、删除/发布/外部写入或权限扩展属于边界动作，必须停下来说明目标与影响并确认。
- 记录候选、Pi 真正发起的 MCP tool call、服务器连接状态及真实成功/失败。认证数据和敏感参数脱敏，不把未经确认的调用显示成完成。
- Pi 1.3.0 会话会连接所有已启用的 MCP servers；`deferred`/`codemode` 只控制模型如何看到/发现 tools，不是按任务懒启动 server。首版按项目过滤启用服务器并验证运行参数/config precedence；server cold-start 编排是后续功能。
- 同名项目 server 可覆盖 user server 某些配置行为；严格使用 Pi 当版本配置规则，不能自行 merge 凭据。
- 不以 `setActiveTools()` 实现完整 deny：Pi 1.3.0 的 codemode/deferred 工具即使不活动仍可能被间接调用。必须在真实工具调用路径校验项目策略，测试直接、嵌套/间接调用与 resource 访问。
- 工具 annotations 是未验证提示，不足以自动批准。trust 不限制 OS 权限，禁止某 Skill 的候选也不能阻止 bash 等通用工具做相同动作；强隔离需另设计。
- Skill 加载不等于工作流正确执行；只有证据足够时显示已加载/已采用，否则显示未知。不得承诺现成 Skill completion 事件。

### 模型和中转站

- 保留 Pi 原生 `/model`、`Ctrl+P` 等；辅助面板仅显示 Pi 实际活动模型。
- Pi 1.3.0 RPC 的 `get_available_models`/`set_model` 仅用于 RPC 模式；扩展侧核对 `ctx.modelRegistry.getAvailable()` 与 `pi.setModel()`。不能把 RPC 命令直接发到 TUI 的 PTY。当版本签名应重新核对；真实 TUI＋PTY＋图形桥组合尚未验证。
- 如果无法读取 TUI 当前模型，第一版如实显示“状态未知”，保留原生切换，不要通过定时塞 `/model` 或解析 ANSI 猜状态。
- 中转站验证前只写草稿。配置变更需精确合并 Pi `models.json` 并保留所有未知字段；凭据使用经批准的秘密存储/认证路径，失败不能覆盖旧配置。

## 技术验证顺序

### 新增模块：任务点智能调度

- 任务点包含输入/产出、依赖、风险、模型能力、Skills/MCP、验收标准及预算；简单任务不要强制额外模型规划。
- 联合选择模型和必要工具；按凭据、上下文、模态、工具兼容、数据披露及项目 allow/deny/confirmFirst 做硬过滤。未知能力或未知价格不能当作支持/免费。
- 推荐首阶段规则＋项目评测，先影子推荐；学习型路由和网关均是可选研究，不自动安装依赖。不能按模型品牌硬编码所谓最强任务分配。
- 自动模式、手动锁定、预算粒度与默认值需明确；任务点间的切换必须由 Pi 确认安全空闲及活动模型，不并发写同一 session，不将 RPC 命令送入 TUI PTY。
- 切换可能发送完整有效会话历史给另一个供应商；检查此前文件/工具结果的披露授权。缓存、加密推理、tool ID 和多模态兼容须测试，不宣称无损交接。
- 质量验收失败先定位证据，再在授权和预算内有限修订/升级；环境/权限失败不盲目换强模型，未知外部副作用不自动重放。
- 统计分类、上下文重发、执行、复核、失败请求的总开销；不默认多模型重复执行。用保留任务集和固定模型基线比较，不承诺研究中的降本数字。

### 实施步骤

1. 先读蓝图、决策、来源和验证记录，再检查工作区及现有原型；不要重建现成资料，不要清理无关文件。
2. **编码前先给用户**：最小实现方案、具体文件列表、依赖及核验到的版本/许可、对原生 Pi 和现有认证/配置的影响、需要运行的验证；等待明确确认后再改代码或安装依赖。
3. 原生窗口基线：Electron 主进程 + sandbox/contextIsolation + 极窄预加载 API + node-pty + xterm.js；启动用户现有 Pi，不对其全局安装或升级。
4. 测 Windows ConPTY：Pi 路径带空格/安装目录、中文 IME 合成输入、快捷键、粘贴、终端 resize、长输出背压、退出/崩溃和 renderer 重载。
5. 仅加入观察型 Pi 扩展读取 session/model/tools 与 MCP/Skill 实际事件；不能改动 Agent 行为。先使用合成/无密钥 fixtures 做测试。
6. 再实施按项目策略的自主路由；不要边写桌面桥边自动调用真实用户服务器。准备隔离、可控的假的 MCP 测试服务器。
7. 测模型切换、API 配置读写和凭据读写前，分别准备隔离配置目录；绝不覆盖用户当前 `~/.pi/agent`。
8. 性能比较固定 Pi 版本、prompt、工具、项目、设备和渲染量，对照原生 TUI；报告原始数据，不预先宣称 Electron 慢/快。

## 初期验收门槛

- 开应用后确实运行用户同一版本 Pi TUI，键盘/中文输入真实到达 PTY。
- 关/重载图形窗口不会冒充 Pi 已完成或丢掉 Pi 的真实状态；退出策略明确。
- 用户有系统终端入口；恢复已有会话前确认原执行者已经退出或完成交接，不承诺活进程无损迁移，不并发写同一会话。
- 项目 A 与 B 的 Skills/MCP 能力不会混淆；未信任项不可被读取并自动运行。
- allow 内任务由 Pi 能自主选择工具；deny 拦截；confirmFirst 触发确认；空候选诚实报告。
- UI 分清能力发现、匹配、实际调用、执行完成；MCP 服务器连接耗时独立标记。
- 模型切换成功/失败均由 Pi runtime 确认；未确认时显示未知/待应用。
- 自动路由同时满足任务点验收、模型工具兼容、项目权限和预算；人工锁定有效，零候选/切换失败/预算不足诚实停止。与固定模型基线比较完整任务质量、时间、费用，而非只比较单次 token 单价。
- 不存在秘密进入普通日志/截图/导出 JSON 的情况；配置写入可回滚。

## 不要做

- 不把桌面 RPC 聊天当作原生 TUI；不解析 ANSI 输出来推断权限、工具和当前模型。
- 不允许 Skill 文本自授文件、网络、凭据或工具权限。
- 不将 Pi trust 或 Electron 弹窗称为 OS sandbox。
- 不假定用户安装的 Claude/Codex/Grok/Trae 模型/API 等价于相应 Agent 引擎接入。
- 不使用受非商业限制的 `zth0828/pi-desktop` 代码作为自由商用产品底座；复用其他候选代码前逐项检查确切 license/notice。
- 不改写用户级配置、不安装/更新用户级 Pi、不运行付费模型调用，除非获得对应明确授权。
