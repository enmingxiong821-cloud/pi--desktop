# 产品与架构决策记录

记录状态：**已确认**代表用户已明确选择；**建议**是当前推荐但未获用户确认；**待验证**需要代码或运行实测，不能按完成处理。

| 编号 | 主题 | 决定/立场 | 状态 | 依据与后续 |
|---|---|---|---|---|
| D-01 | 核心入口 | 打开就是实际 Pi TUI，旁边放图形辅助；终端是主要执行入口 | 已确认 | 用户明确提出“打开就是真实 Pi 终端，旁边有图形辅助” |
| D-02 | 桌面宿主 | Electron 方向 | 已确认 | 用户选择 Electron 开发路线；具体版本/框架待技术安装前核查 |
| D-03 | Pi 执行引擎 | 复用原生 Pi 进程与会话，不重写 Agent loop | 蓝图约束 | 官方原生 TUI 与扩展完整度是目标；真实进程集成仍待验证 |
| D-04 | 中转站与模型 | 支持用户模型选择、自定义中转站、API Key 配置和快捷切换 | 已确认目标 | 原型当前只产生待应用选择，不连 Pi；执行桥和凭据存储待设计/验证 |
| D-05 | 按项目使用能力 | 打开项目后按项目与任务自主选择/调用已授权 Skills/MCP；允许手动指定/禁用 | 已确认目标 | 自动调用在允许范围内无需逐次点选；匹配准确度、真实调用和权限闸门仍待实现验收 |
| D-06 | 能力信任 | 只在已安装/配置且被信任/授权的 Skills/MCP 中自动选择；首次信任或扩大范围明确确认 | 蓝图约束 | Pi 1.3.0 项目 trust 保护项目 MCP/skills/extensions；trust 不是 sandbox |
| D-07 | MCP 运行时 | 首阶段沿用 Pi 会话启用 MCP 的生命周期；不把 deferred 叫作懒启动 | 基于版本文档的设计边界 | Pi 1.3.0 会话启动连接启用服务器；真正 server 按任务 cold start 延后评估 |
| D-08 | 模型切换 | Pi 是唯一真实模型状态源；UI 收到运行时确认才显示切换成功 | 蓝图约束 | Pi TUI / RPC / Extension API 分别提供切换方式，真实终端扩展桥未实现 |
| D-09 | 项目元数据 | 单独的项目 allowlist/policy 可作为未来桌面数据；不代替 Pi 原生配置或 trust | 建议 | 结构、位置、同步策略待进一步需求确认；策略失效不得放宽权限 |
| D-10 | 目标用户 | 首版 Windows 开发工作流 | 规划假设 | 用户希望开发方便；其他用户类型需要调研，不承诺“适合所有人”首版 |
| D-11 | 本地数据库 | 首版无需数据库 | 建议 | 会话与运行仍由 Pi 管理；桌面索引后续确认是否需要本地文件存储 |
| D-12 | 网络后端/端口 | Electron IPC 为优先候选；HTTP 服务未确认，不预分配端口 | 建议/待查 | 1420/2420 是旧候选，不是正式分配；如使用 HTTP 才复核 README 与监听状态 |
| D-13 | 原型 | 独立浏览器原型是交互草案；尚无正式桌面终端、Pi 连接 | 待确认/待实现 | `prototype-design.md` 与 `prototype/index.html` |
| D-14 | 性能 | 不预设 Tauri/Electron 快慢或目标指标，先测对照组 | 待验证 | 尚无桌面进程、PTY 与原生 TUI 对照测量 |
| D-15 | 开源代码复用 | Pi MIT 可依其 LICENSE 复用并保留声明；每个候选分别核查许可，非商业限制代码不得当作自由商用底座 | 蓝图约束 | 见 `sources.md`；发行时还须扫依赖许可与 notice |
| D-16 | 其他引擎 | Claude Code/Codex/Grok/Trae 不默认并入首版、不假设共享 Pi 会话 | 延后 | 模型与 Agent 引擎是不同层；集成需逐家核实公开契约 |
| D-17 | 任务点自动模型路由 | 按项目任务点自动选择模型，并与 Skills/MCP 联合形成执行方案 | 已确认目标 | 质量、安全、隐私约束优先；通过项目任务集优化总时间/费用。见 `task-routing-design.md`；尚未实现/实测 |
| D-18 | 自动路由实现顺序 | 规则/能力过滤＋项目评测，先影子推荐，再安全边界自动应用 | 建议/待验证 | 不强制引入学习型分类器或额外网关；不按品牌写死能力排名 |

## 尚待产品确认

- 静态原型的视觉/交互布局是否作为正式 UI 起点；用户尚未正式确认原型。
- Skills/MCP 首次信任的提示是否分为“本次允许”和“永久允许”。
- 按项目自主调用是已确认目标；建议允许范围内无需逐次点击。待确认具体授权粒度、默认是否展开候选及多候选/低置信度时如何处理。
- 项目 policy 的命名、存储、是否纳入 git、协作共享方式。
- API Key 的 Windows 凭据保存方式、密钥删除/迁移体验。
- 仅用用户既有 Pi，还是提供应用内安装/版本管理（必须先用户授权安装范围）。
- 路由默认质量/均衡/速度模式、自动应用授权范围、任务/项目预算及有限升级上限；保留人工锁定和关闭自动路由。
