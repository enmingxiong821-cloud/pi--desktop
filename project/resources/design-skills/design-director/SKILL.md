# 设计总控（Design Director）

这是本机所有 UI 设计任务的入口。只要任务会改变界面的**外观、层级、布局、排版、配色、动效或交互感受**，就先按本 Skill 执行，不必等用户说出“设计”二字。

四个专项 Skill 已全局安装，各自擅长不同表面。不要同时把它们全部读完：按本文件的裁决选择一个主 Skill，最多再加两个辅助，只读需要的参考文件。

## 一、不可违背的顺序

1. **用户 brief 最高。** 用户指定的风格、年代、材质、字体、配色，即使与下面的“反套路”清单冲突，也照做。
2. **项目既有设计系统次高。** 先读 `DESIGN.md`、`PRODUCT.md`、`CLAUDE.md` / `AGENTS.md` 中的设计约定，以及现有 CSS 变量、组件和页面。改版要保留既有身份；只有用户明确要求重做时才替换视觉世界。
3. **可访问性与可用性是底线。** 任何审美选择都不能牺牲对比度、键盘操作、焦点可见、触控尺寸和减少动效偏好。
4. **最小侵入。** 不顺手重构无关组件，不引入新依赖；需要新字体、图标库或动画库时先说明再安装。

## 二、先判断表面类型

不同表面用不同主 Skill，混用会得到“四不像”。

| 表面 | 成功标准 | 主 Skill | 辅助 |
|---|---|---|---|
| Persuade：落地页、官网、活动页、定价页、作品集 | 让人愿意继续看并采取行动 | `design-taste-frontend` | `frontend-design` 定方向；`ui-ux-pro-max` 查数据 |
| Operate：Dashboard、后台、编辑器、设置、工具 | 任务完成得快、状态清楚 | `impeccable` | `ui-ux-pro-max` 查 UX/可访问性规则 |
| Read：文档、文章、帮助中心、更新日志 | 读得懂、读得久 | `impeccable` | `ui-ux-pro-max` 查排版与可读性 |
| Experience：画廊、展示、沉浸式体验 | 作品本身主导，界面退后 | `design-taste-frontend` | `frontend-design`；`impeccable` 查动效 |

**冲突裁决：** 同一件事出现不同规则时，按“用户 brief → 项目规范 → 主 Skill → 辅助 Skill → 通用经验”的顺序取第一条，不做折中拼接。`ui-ux-pro-max` 的数据与清单是参考，不是覆盖用户意图的硬指令。

## 三、工作流

### 1. 侦察（不改代码）

- 识别技术栈：`package.json`、`pubspec.yaml`、`*.xcodeproj`、`composer.json` 等；不要假设框架。
- 找到现有 token、组件、布局壳、暗色模式和响应式断点。
- 能运行就先运行，截取目标页面的当前状态；不能运行就以现有截图、golden 或代码为准。
- 明确这次是**精修**（保留身份）还是**重做**（替换视觉世界）。用户没说清时按精修处理。

### 2. 定方向（先文字，后代码）

写一个紧凑的设计计划，再动手：

- **配色**：4–6 个命名 hex 值，说明各自职责（底色、表面、正文、弱化、强调、状态），并给出暗色对应关系。
- **字体**：1–2 个家族，说明展示/正文/数据角色、字号阶梯、行高与字重；不要用“默认再默认”的 Inter + 灰卡片组合。
- **布局**：一句话概念 + ASCII 线框，标出对齐方式、栅格、首屏焦点和滚动节奏。
- **原则**：3 条只属于这个 brief 的判断，例如“信息密度优先于留白”“所有状态用同一套边框语言”。
- **记忆点**：只选一个让人记住的元素；其余保持安静。

写完对照 brief 自问：把产品名换掉后，这套方案是否仍适用于任何同类产品？如果是，重做方向，不要进入编码。

### 3. 建设计系统

- 用语义 token（`--bg`、`--surface`、`--text`、`--muted`、`--accent`、`--danger`、`--radius`、`--space-*`），组件里不写裸 hex。
- 间距用 4/8 的倍数；圆角、阴影、边框各限一套层级，不要每个卡片都同一圆角同一阴影。
- 覆盖状态：default / hover / active / focus-visible / disabled / loading / empty / error。
- 暗色模式不是反色：重新定表面层级与强调色对比。
- 需要具体风格、行业配色、字体配对、图表或某框架实现建议时，再查 `ui-ux-pro-max`：

```bash
python "C:/Users/Caspian6610/.pi/agent/skills/ui-ux-pro-max/scripts/search.py" "<产品类型 行业 关键词>" --design-system
python "C:/Users/Caspian6610/.pi/agent/skills/ui-ux-pro-max/scripts/search.py" "<具体问题>" --domain <ux|style|color|typography|icons|chart|gsap>
```

只采用与当前产品、平台和 brief 对得上的结果；查不到就明说，不要编造数据。

### 4. 实现

- 语义化 HTML；标题层级连续；交互元素用真实 `button` / `a` / `input`，不要给 `div` 加点击。
- 焦点样式必须可见；图标按钮必须有可访问名称；图片有替代文本。
- 触控目标至少 44×44px；正文不小于 16px（数据密集界面最小 12–13px 并保证对比度）。
- 布局先移动端，再增强到桌面；禁止横向滚动；长文本行宽约 60–80 字符。
- 动效只用于解释状态变化；尊重 `prefers-reduced-motion`。
- 不引入未说明的依赖；复用项目既有工具函数与组件。

### 5. 看结果，再修

- 至少检查 375px、768px、1440px 三个宽度；有条件就看真实渲染截图，而不是只看代码。
- 每个宽度检查：首屏是否有明确焦点、是否溢出、文字是否截断、层级是否清楚、暗色是否可读。
- 一次看完再批量修，避免“改一处截一张图”的低效循环。
- 最后跑项目已有的类型检查、构建和冒烟；UI 功能要在浏览器里实际点过再报告完成。

## 四、反“AI 味”清单

以下不是绝对禁止，而是**未经 brief 指定就不要用**的默认答案：

- 米白/奶油底 + 高对比衬线大标题 + 陶土色强调（尤其接近 `#D97757`）。
- 近黑底 + 单一荧光绿/朱红强调。
- 每个标题上方都加全大写、字距拉开的 eyebrow 标签。
- 所有内容切成同一圆角、同一柔和阴影的卡片；用渐变蒙层当装饰。
- 居中三行大标题 + 一行副标题 + 两个按钮的万能首屏。
- 用 emoji 当图标；用 `→` 结尾所有链接和按钮。
- 每个 section 都做 fade-and-slide-up 入场；每张卡片都做 hover 位移。
- 编号 `01 / 02 / 03` 用在并非序列的内容上；用中点在元信息里拼接 `A · B · C`。
- 文案里出现 “seamless / empower / unlock / elevate / 一站式 / 赋能 / 无缝” 等空词。
- 使用与主题无关的占位图、假 logo 墙和虚构客户评价。

## 五、文案与内容

- 首屏写清楚“这是什么、给谁、解决什么问题”，用具体名词和动词，不写正确的废话。
- 标题与正文语气一致；同一页面不要一半口语一半企业腔。
- 占位内容也要像真实内容：真实字段名、真实数量级、真实状态；不要 lorem ipsum 出现在可见首屏。
- 不用夸张承诺，不虚构数据、客户或奖项。

## 六、动效与微交互

- 一个页面只安排一个主入场序列或一个主滚动叙事，其余保持安静。
- 界面反馈 120–240ms；展开/收起可到 280ms；超过 400ms 必须有明确理由。
- 优先 transform / opacity；不要动画 width、height、top、left。
- hover 只做轻微颜色/边框/位移变化，不做大幅缩放或持续漂浮。
- 加载态用骨架或明确进度；不要只转一个没有说明的圈。
- `prefers-reduced-motion: reduce` 时移除位移与视差，保留必要的状态切换。

## 七、交付前自检

- [ ] 首屏有一个明确焦点，且与产品本身有关。
- [ ] 配色、字体、圆角、阴影、间距各自成体系，没有随手值。
- [ ] 375 / 768 / 1440 宽度无横向滚动、无遮挡、无截断。
- [ ] 键盘可完整操作，焦点可见，图标按钮有名称。
- [ ] 正文与背景对比度达标；暗色模式单独检查过。
- [ ] 空、加载、错误、禁用、成功状态齐全。
- [ ] 动效克制，并支持减少动效。
- [ ] 文案具体，没有空词和假数据。
- [ ] 只改动了任务相关文件；没有顺手重构。
- [ ] 类型检查、构建、既有测试通过；UI 在浏览器中实际验证过。
