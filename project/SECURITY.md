# 安全策略

## 支持的版本

安全修复优先进入最新发布版本，并尽量回移到上一个次版本。

| 版本 | 支持 |
| --- | --- |
| 1.5.x | 是 |
| 1.4.x | 仅关键修复 |
| 更早版本 | 否 |

## 报告漏洞

请不要在公开 issue 中披露未修复的漏洞。

1. 打开仓库的 **Security** 页，选择 **Report a vulnerability**，通过 GitHub 私密报告提交。
2. 说明影响版本、复现步骤、影响范围与可能的修复方向。
3. 如果问题涉及密钥泄漏，请立即在报告中说明，但**不要附上真实密钥**。

一般会在 7 天内确认，并在修复发布后于变更记录中致谢（如你愿意署名）。

## 安全边界

本项目按以下边界设计，超出边界的请求不会被接受：

- 只读取本机 Pi 配置判断模型与能力，不读取密钥内容。
- 不读取、不回显、不写入日志的敏感信息包括：API Key、Token、密码、Cookie、私钥。
- 项目配置导出与模板不包含环境变量值；环境变量只保存在本机 `userData/project-env.json`。
- 抓取只访问公开 http/https 页面，遵守 robots.txt 与按主机限速。
- 逆向分析只处理本机文件；授权渗透必须先完成目标授权校验，默认被动，主动扫描逐次授权。
- 不提供未授权远程扫描、CIDR / 网段扫描、fuzz、爆破、DoS、漏洞利用或规避检测能力。
- 外部工具在用户确认后安装，不静默安装，不随安装包分发第三方二进制。
- 不修改用户既有的 Pi 配置；一键配置只安装 Pi 本身。

## 依赖与供应链

- 依赖更新通过 Dependabot 与人工审查进入主分支。
- 发布产物由本地或 CI 构建，安装包与便携版均未签名，请从本仓库 Release 下载。
